# 热点取证与写作

目标：核心事件有依据就围绕它写。保留能解释问题的具体材料，局部事实错误局部修正；仅核心事件无法确认时因资料不足停止成稿。工具或格式错误单独报告。事实安全与编辑质量分别记录，不以完成调用或通过单测代替内容验收。

## 处理流程

1. 沿用热点来源、目标识别和正文读取。过滤混用对象/版本的结果，优先读取原始链接及相关来源；只取得搜索摘要不算取得正文。核心事件不明时最多补查一次。
2. 一次事实整理同时确认核心事件、提取有用细节。每个断言对应足以支持它的原文摘录。Markdown 转为可见文本后定位引用，保留数字、单位、版本和否定词；匹配成功不等于语义充分，后续仍需核对引用是否支持具体断言。
3. 动态资料按快照保留，记录来源、采集时间和使用范围。采集时间不等于源数据产生时间，不能冒充实时状态。`unsupported_claims` 只记录具体无依据断言及原因，不禁写整个类别。
4. 写作在同一次模型调用返回 `outline` 与正文。提纲记录读者、具体问题、回答、论证顺序和对应事实，供复核与排查使用，不进入文章。材料少时写短稿，不凑条数和篇幅。
5. 复核区分事件事实、基础概念解释和分析。事实需要相应正文；准确的常见概念无需新闻逐字提供定义；关键或存疑的专业解释可在首轮申请最多两个定向背景查询。分析核对事实前提和推理，不要求来源作者说过同样观点。背景知识不能推断本事件未披露的细节。
6. 每个事实问题必须指出原文中唯一可定位的具体断言、原因和修正建议，不能因一句错误删除整段。首次发现事实或实质编辑问题，沿用一次完整改稿。终检优先核对问题是否解决、新改断言和上下文衔接，不无故推翻已成立内容或重新选角度。
7. 仍有事实问题时最多进行一次局部替换，再独立复核。此后不无限循环：尚未解决的断言所在句子从交付正文剔除，其余材料保留，标记 `needs_edit` 并提示检查衔接；不能把这种降级稿标为通过。事实无误但仍有实质编辑意见的稿件也标为 `needs_edit`，保存给用户继续编辑。

## 状态与接入

- `approved`：本轮未报告待修事实或实质编辑问题，不等于已发布或保证绝对正确。
- `needs_edit`：初稿存在，仍需编辑；原因列在文章之外，并随记录保存。
- `blocked`：核心事件无法确认，无文章。
- `error`：工具或输出契约异常，不能误报为资料不足。

热点雷达、工作台、选题库入口均传递 `hotTopic`。来源与上一稿按会话保存。还没有初稿时，下一条消息继续生成初稿。已有初稿后，只有消息写明改稿、重写或重新生成才再走该流程；其余消息按普通对话回答，并附上选题和上一稿。`approved` 和 `needs_edit` 均保存为初稿，不自动发布；未进入热点会话的普通对话不受影响。

## 记录与配置

- `outputs/_sessions/hot-topics/<会话哈希>/context.json`：来源与上一版初稿。
- 同目录 `<轮次哈希>.json`：检索、正文、事实及快照口径、未核实断言、提纲、每轮稿件/复核、局部修复和最终状态。
- `outputs/热点创作-<会话哈希>/初稿-<轮次哈希>.md`：文章。待编辑原因保留在会话结果和取证记录，正文不混入内部处理日志。

沿用当前 Gateway 的 `web_search`、`tavily_extract`、`web_fetch` 和 `llm-task`，模型与凭证不另配。模型调用不加载工具，JSON 输出契约同时提供给模型和插件。首次启用：

```bash
python3 scripts/configure_hot_topic.py --config /root/.openclaw-easel/openclaw.json
bash scripts/gateway.sh restart
```

模型 JSON/契约错误，以及 `llm-task` 的 HTTP 500，最多重试当前模型步骤一次，保留原材料和已完成阶段，记录 `model_retries`。当前 Gateway 会把内部异常隐藏为通用500，客户端不能保证区分格式错误和其他执行失败；模型步骤没有发布等副作用，故仅对这一工具做一次有上限重试。明确的401/403/404、其他工具错误不重试；持续失败仍报告工具错误，不归为资料不足。

超时集中在 `easel/timeouts.py`。断线不取消后台任务，显式停止不交付。

## 验证与人工验收

自动测试只验证程序行为，不调用真实模型、平台或网络。提交前运行贡献指南的两个校验脚本和 `python -m pytest tests/`。

模型验收使用独立命令，显式调用当前模型，以冻结正文排除搜索变化；不访问新网页、不发布、不写生产会话：

```bash
python scripts/replay_hot_topic.py --input /path/to/saved-report.json --output /tmp/hot-topic-acceptance-new --live-model
```

输入可直接使用历史取证记录，也可使用含 `topic`、`documents` 和可选 `request`、`profile` 的 JSON。背景补查请求在冻结回放中仅记录，不获取新资料。输出目录必须不存在，结果包括完整取证记录、文章和状态。

`tests/fixtures/hot_topic/` 提供明确标记的虚构人物、产品、简短通知样本，用于检查跨选题行为，不得作为真实新闻发布。另用历史真实失败案例的正文做对照，完整网页保留在本地/服务器验收目录，不提交到仓库。

验收逐篇检查：有用细节及解释是否保留；具体断言是否越过材料；人物事件是否捏造动机/去向；产品参数是否混淆单位或冒充实测；材料少时是否简洁成稿；删改是否损伤衔接；提纲问题是否得到回答；是否重复判断边界。一次样例成功不能证明所有选题稳定通过。
