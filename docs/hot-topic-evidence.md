# 热点取证与写作

目标：核心事件有依据就围绕它写；缺乏依据的细节删除，观点明确作为分析。只有核心事件无法确认，才因资料不足停止成稿。工具错误、格式错误须单独说明，不能归为资料不足。

## 实现

1. 确定性提取型号与版本，规范空格/连字符拼写，保留准确版本。检索中文事件词和英文来源词；目标涉及训练时直接搜训练与直播，不要求模型已发布。
2. 读取入口及用户提供的链接，从搜索结果中优先读取匹配目标版本的正文；过滤未提及目标版本的搜索结果。Tavily 正文提取失败时使用 web_fetch。摘要不是正文证据，重复正文去重，每轮最多读六个页面。
3. 模型区分最小核心事件、已有依据的细节和需要删去的细节。核心证据引用必须存在于实际取得的正文。训练面板、当事人说明、可靠报道等均可支持相应事件，不设置必须有官方公告或固定来源数量的门槛。
4. 核心事件不明时补查一次，可追踪正文中真实出现的相关链接。核心已确认则直接写稿，不为补齐成本、Token数或最终成绩而延迟写作。
写作阶段先在内部确定读者、文章问题、核心判断及支撑事实的意义，不另增模型调用或对外输出提纲。解释术语与数字、删去无法解释的装饰性信息，避免重复结论和多段免责声明。

5. 独立复核标题、角度及每个段落。复核同时通过 `editorial_notes` 提供最多五条实质编辑意见（标题回应、解释、段落推进、重复等）。局部事实不支持或有编辑问题时，沿用原有的一次改稿，再复核；仍无依据的段落删除，保留有依据的正文。只有复核否定核心事件时才按核心依据不足处理；格式不全或无法形成有事实依据的正文报告处理异常。

检索方案不由模型重新选择型号，避免被旧版本资料带偏。所有模型阶段使用同一已配置模型的独立调用，禁用工具；输出契约同时传给模型与插件校验器。纯编辑问题不会否定核心事件或阻止交付，第二次复核仍可记录未解决的编辑意见，不追加循环。改稿中的事实断言仍照常复核。模型判断仍可能出错，自动复核不等于人工确认。

## 接入与记录

热点雷达、工作台、选题库的“做内容”传递 `hotTopic`。服务器保存会话来源，续写和重试不绕过取证。普通对话不受影响。热点会话处理初稿与修改；附件、配图和发布等使用对应入口或普通对话。

- `outputs/_sessions/hot-topics/<会话哈希>/context.json`：来源及上一版已交付初稿。
- 同目录 `<轮次哈希>.json`：搜索结果、已读正文、核心证据、忽略细节、复核和删除记录。
- `outputs/热点创作-<会话哈希>/初稿-<轮次哈希>.md`：已交付文章。未通过的中间稿不出现在内容库。

沿用 Gateway 的 `web_search`、`tavily_extract`、`web_fetch` 和内置 `llm-task`，沿用现有模型与凭证。首次启用内置工具：

```bash
python3 scripts/configure_hot_topic.py --config /root/.openclaw-easel/openclaw.json
bash scripts/gateway.sh restart
```

不需要升级 OpenClaw；配置脚本保留既有设置并备份。启用后 Web 与 Gateway 均需正常运行。超时统一在 `easel/timeouts.py`。断线不取消后台任务，显式停止不交付；已经发出的上游请求可能运行至其自身超时。

## 验证

离线测试覆盖“训练中但无发布公告/完整成本仍可写”、错误细节删除、核心无法确认才阻断、准确型号检索、旧版本过滤、结构契约可见性及会话恢复。执行贡献指南的两个校验脚本及 `python -m pytest tests/`，前端执行 `npm test` 和 `npm run build`。

生产验收应以用户实际选题得到的文章与取证记录为准，不以健康检查或模拟测试代替实际结果。
